### What does CPython do

Suppose we create `app.py` with below code inside,

```python
print("Hello")
```

The file `app.py` is called **Python Source Code**. Python source code files will always have .py extension. This .py extension denotes that this file is not executable by the CPU.
The CPU understands only Machine Instructions. So somebody has to translate it. That job is done by CPython. It reads the app.py and starts processing it. CPython,

- reads source code
- translates it
- executes it.

CPython also contains a compiler essentially making it both, An interpreter and a Compiler. Here is how the roles are actually devided between the compiler and the interpreter inside CPython:

```
Source Code (.py)  ──►  [ COMPILER ]  ──►  Bytecode (.pyc)  ──►  [ INTERPRETER ]  ──►  CPU Execution
```

#### 1. Compiler Job (Source Code $\rightarrow$ Bytecode)
- **Reads and Parses:** The compiler reads `app.py` source code, checks syntax and parses it into an Abstrat Syntax Tree (AST).
- **Compiles / Translates to Bytecode:** The compiles translates that AST into low-level intermediate instructions called bytecode (stored as .pyc files or in memory)

> *Note:* Bytecode is **not** machine code; it is a set of instructions designed specifically for Python's virtual machine.

#### 2. Interpreter Job (Bytecode $\rightarrow$ Machine Execution)

* **Reads Bytecode:** CPython's Virtual Machine loop reads the compiled bytecode instructions one by one.
* **Translates & Executes:** The interpreter translates each bytecode instruction into native CPU machine instructions and executes them on your physical hardware immediately.

#### Correcting the Steps

| Step | Action | Responsible Component | Target Output |
| --- | --- | --- | --- |
| **1. Read & Parse** | Parses `.py` source code structure | **Compiler** | Abstract Syntax Tree |
| **2. Compile** | Translates AST to intermediate instructions | **Compiler** | Bytecode (`.pyc`) |
| **3. Read Bytecode** | Loads bytecode instructions line by line | **Interpreter** | In-memory evaluation |
| **4. Execute** | Translates bytecode to CPU actions & runs them | **Interpreter** | Physical Machine Code / CPU execution |

The **compiler** handles everything up to generating the **bytecode**, while the **interpreter** takes over from the bytecode to **final CPU execution**.

### AST - Abstract Syntax Tree

An Abstract Syntax Tree is a hierachical, tree-structured representation of code generated by a compiler or interpreter during the parsing phase.

For the statement `x = 5 + 3`, an AST respersents the assignment operation as a root node, with hthe target variable on the left and the addition expression on the right:

```
AssignmentExpression (=)
              /          \
  Identifier (x)       BinaryExpression (+)
                            /         \
                 Literal (5)           Literal (3)
```

- **Root Node:** The assigneent operator (`=`), holding the overall operation.
- **Left Child:** The variable `x` where the evaluated result will be stored.
- **Right Child:** Abinary operation node (`+`) that evaluates two leaf children (`5` and `3`).

## Stage 4 - Compiler

CPython has a compiler. It takes `AST` and converts it into `Bytecode`.

### What is Bytecode

Bytecode is a simplified instruction language designed for Python Virtual Machine.

Example:

```python
x = 5
print(x)
```

roughly becomes

```
LOAD_CONST 5

STORE_NAME x

LOAD_NAME print

LOAD_NAME x

CALL

POP_TOP

RETURN
```

These are not CPU instructions, these are instructions for Python Virtual Machine.

The Bytecode is usually stored in `__pycache__/`. It is stored as example `app.cpython-314.pyc`. The pyc file stores the bytecode.
The Bytecode can be thought of as a compiled code cache. CPython doesn't have to compile the code again if the Bytecode is already available. CPython vcan direcyly load the Bytecode leading to faster startup.

#### Why Bytecode First

Python source code is converted to bytecode first primarily for performance and platform independance.

- **Faster Execution:** Parsing human-readable source code text line-by-line is extremly slow. Converting it into a compact low-level bytecode format allows Python to skip parsing on subsquent runs, speeding up execution drastically.
- **Platform Independence:** Machine code is specific to a chip architecture (like Intel x86 or ARM). Bytecode is a universal, middle-ground language. It can run on any operating system or device that has a Python interpreter.
- **Easier Interpretation:** The Python Virtual Machine (PVM) can process a standardized, simple set of bytecode instructions much more effitiently than a complex tree of raw text.

## Stage 5 - Python Virutal Machine (PVM)

This component is an interpreter part.
It is a software written in C which lies inside CPython.
The PVM executes Bytecode instruction by instruction and converts them to Machine Instructions that CPU understands.

The PVM acts as a bridge between the universal bytecode and your specific hardware.

### How the PVM handles the CPU

- **Pre-compiled for your system:** When you install Python, you download a specific version build for your exact operating system and CPU architecture (such as Windows x64 or macOS M-series ARM).
- **Real-time translation:** Because the PVM is already tailored to your specific machine, it knows exactly how to translate each universal bytecode instruction into precise 0s and 1s (Machine code) that your specific CPU understands.
- **Just-in-time adaption:** The PVM reads a line of bytecode, determines the appripriate hardware-level operations for your system, and passes them to the CPU to execute immediately.

### Does the PVM convert bytecode at runtime, live in memory and start when the code is run?

- **The PVM starts instantly:** When you type `python script.py`, the very first thing you operating system does is load the executable Python program (which contains PVM enigne) into RAM.
- **It lives entirely in memory:** The PVM is a software execution loop. It allocates space in your computer's RAM to track variables, the call stack and the loaded bytecode.
- **It evaluates at runtime (with a slight nuance):** When CPython is compiled from C into an executable, all possible bytecode instructions are built into it. Standard Python (CPython) does not technically emit a separate, physical machine code file at runtime. Instead PVM reads bytecode instruction (e.g `BINARY_ADD`) and triggers it's own internal pre-compiled C-code functions to make the CPU perform the addition immediately.

### Pre-parsing techniques for production deployment.

If you deploy a large Python application, the very first execution can suffer from a "startup lag" because Python has to parse the raw text of hundreds of .py files and compile them into bytecode.

To prevent this delay in production systems, use Ahead-of-Time (AOT) Bytecode Compilation.

#### The Standard Production Solution: compileall

Python has a built-in module called [compileall](https://docs.python.org/3/library/compileall.html) designed specifically for deployment pipelines. You run this during your build process (e.g., inside your Dockerfile) to bake the bytecode directly into the deployment package.

Run this command in your project root before deploying:

```bash
python -m compileall .
```

- **What it does:** It recursively scans your entire project, parses all .py files, and pre-generates .pyc (compiled bytecode) files inside __pycache__ folders. [10, 14, 15] 
- **The Production Benefit:** When your server starts up or receives its first API request, the PVM detects the .pyc files, skips the text-parsing step entirely, and loads instantly into memory.


#### Production Best Practice for Docker & Containers

If you use Docker, a highly secure and optimized pattern is to pre-compile the code and then lock down the file system so it is read-only: [10, 11] 

```dockerfile
# 1. Copy your source code
COPY . /app
WORKDIR /app

# 2. Pre-compile everything into bytecode ahead of time
RUN python -m compileall .

# 3. Optional: Prevent Python from trying to write any new bytecode at runtime
ENV PYTHONDONTWRITEBYTECODE=1
```
